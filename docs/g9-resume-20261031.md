# G9 唤醒后不可用：隐藏规则误匹配虚拟手柄

## 现场与临时恢复

2026-10-31 01:31 唤醒后，G9 USB `3537:1136` 已正常重新枚举，
InputPlumber 的 CompositeDevice 可响应，物理输入源和虚拟 Steam Deck target 都存在。
现场运行的是 `inputplumber-udev-fix 0.83.0-3` 与 `y700-g9 1.2.0-1`；
此前准备的新包还没有安装。

直接阻断点在虚拟手柄的访问权限：

- 虚拟 Steam Deck `28de:12f0` 占用了 `/dev/hidraw0`。
- `/run/udev/rules.d/50-inputplumber-hide-hidraw0-early.rules` 及配套 late 规则
  从 10 月 30 日 21:48 留存，匹配条件只有 hidraw 子系统和 `KERNEL=="hidraw0"`。
- 该规则将虚拟节点设成 0000、清除用户 ACL，并加入 `inputplumber/by-hidden`。
- Steam `controller.txt` 能发现虚拟设备，但反复报 `Unable to open local device: /dev/hidraw0`；
  没有进程打开该节点。

备份并删除这两个过期规则、重载 udev 后，节点恢复为 0660，`alarm` 获得读写 ACL。
重新创建虚拟 target 后，原 Steam 进程成功打开设备，InputPlumber 和 Steam 均未重启。
只读采样收到每秒约 251 份虚拟报告，用户确认方向键和摇杆已恢复正常。

## 修复范围

[InputPlumber 本地补丁 0002](../packages/inputplumber-g9-2026/0002-scope-hidraw-hide-rules-to-device-path.patch)
让 hidraw 隐藏规则同时匹配原设备的完整 `DEVPATH`。设备断开后，其他物理设备或
InputPlumber 自己的 UHID target 即使复用同一 hidraw 编号，也不再命中过期规则。
缺少设备路径时不生成仅匹配编号的规则。

这是官方 v0.83.0 的 `Device::get_match_rule()` 中已有的匹配问题。
新包 `inputplumber-g9-2026 0.83.0-2` 保留 G9 震动驱动并加入此项修复；
不包含此前暂缓的 Manager 设备发现/移除补丁。`manager.rs` 和 `udev/mod.rs`
与官方归档逐字节一致。
